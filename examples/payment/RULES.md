# 페이링 결제 승인 데모 — 규칙 명세

> **승인 상태:** 사용자가 요청 시 "규칙 명세는 파일로 남기고 미리 승인한 걸로 치고 끝까지 진행"이라고 사전 승인함 (2026-10-08).
> 아래 "가정" 항목은 브리프에 없던 부분을 기본값으로 채운 것이라 미팅 전 확인이 필요합니다.

## 브리프에서 확정된 것
- 대상: 카드사 미팅 시연, 모바일 앱, 시안 없음 → 페이링 브랜드 컬러로 깔끔한 기본 UI
- 플로우: 가맹점 QR 스캔(모의) → 결제 금액 확인 → 지문 인증(1초 길게 누르기) → 3초 취소 가능 → 승인 요청 → 승인/거절 결과
- 규칙: 네트워크 끊김 시 같은 거래번호로 재시도·이중 결제 금지 / 승인 대기 10초 초과 시 '확인 중' + 결과는 알림 / 잔액 부족 시 거절 / 승인 후에는 취소 불가, 환불 요청만
- 발표자 조작: 네트워크 끊기, 카드사 응답 지연, 거절, 잔액 부족

## 엔티티
| 엔티티 | ID 형식 | 생성 시점 | 중복이 생기지 않는 이유 |
|---|---|---|---|
| 결제 거래 | TX-0001 | 3초 취소 가능 시간이 끝나는 순간 | `commit()`이 진행 중 거래가 있으면 아무것도 하지 않음. 재시도는 기존 ID를 재사용 |
| 카드사 승인 원장 항목 (모의 서버) | 거래번호와 동일 | 서버가 거래번호를 처음 수신할 때 | 서버는 거래번호를 멱등 키로 사용. 같은 번호 재수신 시 새로 처리하지 않고 기존 결과 반환 |
| 환불 요청 | RF-0001 (거래번호 숫자 재사용) | 승인 완료 거래에서 '환불 요청' | 거래당 한 번만 허용 |

## 불변 조건
- 진행 중 결제는 하나뿐. 버튼 연타·재시도·화면 이동으로 두 번째 거래번호가 생기지 않는다.
- 거래번호는 재시도·재연결·확인 중 전환을 거쳐도 바뀌지 않는다.
- 한 거래번호에 대한 출금은 최대 1회. 같은 번호 재요청은 기존 결과를 돌려준다.
- 3초 취소 가능 시간이 끝나기 전에는 어떤 요청도 전송되지 않는다.
- 거절된 거래는 출금하지 않는다.
- 승인 요청이 전송된 뒤에는 '취소'가 없다. 승인 후 되돌리기는 '환불 요청'뿐이며 거래당 1회.

## 예외
| 상황 | 화면 | 규칙 |
|---|---|---|
| 요청이 서버에 닿기 전 네트워크 끊김 | "연결이 끊겼어요 · 같은 거래번호로 자동 재시도" | 복구 시 같은 번호로 재전송, 서버는 처음 받는 것으로 처리 |
| 서버 승인 후 응답이 오는 중 끊김 (응답 유실) | 위와 동일 | 복구 시 같은 번호로 재전송 → 서버가 "이미 승인된 거래" 결과를 반환, 추가 출금 없음 |
| 승인 시점에 이미 오프라인 | 요청 화면 + 오프라인 안내 | 거래번호는 생성, 복구 시 전송 |
| 카드사 응답 지연 | 대기 초 표시 → 10초 후 '확인 중' | 앱은 홈으로 나갈 수 있음, 결과 도착 시 알림 |
| 카드사 거절 | 결제 실패 · "카드사에서 승인을 거절했어요" | 출금 없음 |
| 잔액 부족 | 결제 실패 · "연결 계좌 잔액이 부족해요" | 카드사 승인 단계에서 거절, 출금 없음 |
| 확인 중에 새 결제 시도 | 토스트 "확인 중인 결제가 있어요" | 새 거래 시작 불가 |
| 요청 전송 후 취소 시도 | 취소 버튼 없음 / 콘솔에서 시도 시 안내 | 승인 후엔 환불 요청만 |
| 오프라인에서 환불 요청 | 토스트 "네트워크 연결 후 다시 시도해 주세요" | 요청 생성 안 함 |
| 지문 1초 전에 손 뗌 / 버튼 밖으로 이동 / 창 전환 | 인증 화면 유지 | 아무것도 전송 안 함 |

## 모의 처리 (실제로 일어나지 않는 것)
- QR 카메라, 지문 센서, 네트워크, 페이링 서버, 카드사, 계좌 잔액, 푸시 알림: 전부 메모리 안에서 흉내. 새로고침하면 초기화.
- 가맹점·카드·금액은 모두 가상 데이터 (브루잉랩 성수점, 가온 체크카드 ****1234).

## 가정 (확인 필요)
1. 결제수단은 페이링에 연결된 **체크카드**이고, '잔액'은 연결 계좌 잔액. 잔액 부족 판정은 카드사 승인 단계에서 한다(앱이 미리 막지 않음).
2. 거래번호는 3초 취소 시간이 끝나는 순간 생성된다(취소된 결제에는 번호가 없다).
3. 10초는 첫 승인 요청 시점부터 센다(오프라인 시간 포함).
4. 재시도는 네트워크 복구 시 자동. 온라인인데 응답이 늦는 경우 앱은 재전송하지 않고 기다린다(확인 중 → 알림).
5. '확인 중'인 동안에는 새 결제를 시작할 수 없다.
6. 환불은 요청 접수 후 2.5초 뒤 자동 완료로 연출(실제 정책·소요기간은 카드사 협의 사항).
7. 지문 인식 실패, 카메라 권한 거부, QR 인식 실패는 브리프에 없어 이번 범위에서 제외.
8. UI 언어는 한국어, 기기 크기 390×844, 정적 파일로 오프라인에서 열림.
