# 페이링 결제 승인 플로우 — 시연 데모

카드사 미팅용 인터랙티브 데모입니다. 왼쪽은 실제처럼 조작되는 모바일 앱 화면, 오른쪽은 발표자 콘솔입니다.
설치할 것은 없고 인터넷 없이도 동작합니다.

## 여는 법
- `index.html`을 더블클릭해서 브라우저(Chrome/Edge)로 엽니다. 서버는 필요 없습니다.
- (선택) `node server.cjs`를 실행하면 http://127.0.0.1:4173 에서도 열립니다.
- 새로고침하면 모든 상태가 처음으로 돌아갑니다.

## 발표하는 법
- 오른쪽 위 **발표 모드**: 콘솔을 숨기고 휴대폰 화면만 가운데에 보여 줍니다. 단축키는 발표 모드에서도 그대로 동작합니다.
- 휴대폰 화면은 직접 눌러도 되고(지문은 마우스로 1초 길게 누르기, 키보드는 스페이스 길게), 시나리오 자동 재생을 써도 됩니다. 콘솔 버튼을 누르면 자동 재생이 멈추고 그 상태에서 수동으로 이어집니다.

### 시나리오 (숫자 키 1–7)
| 키 | 시나리오 | 보여 주는 것 |
|---|---|---|
| 1 | A 정상 승인 | QR 스캔 → 금액 확인 → 지문 1초 → 3초 취소 가능 → 승인 요청 → 결제 완료 |
| 2 | B 3초 안에 취소 | 취소하면 거래번호도 만들어지지 않고 아무것도 전송되지 않음 |
| 3 | C 응답 유실 → 같은 번호 재시도 | 카드사가 승인한 직후 응답이 오는 중에 네트워크가 끊김 → 복구 시 TX-0001로 재전송 → 서버가 기존 승인 결과를 돌려줌. 콘솔의 **요청시도 2회 / 서버수신 2회 / 출금횟수 1회**가 핵심 장면 |
| 4 | D 응답 지연 → 확인 중 → 알림 | 카드사 무응답 10초 → '결제 확인 중' → 홈으로 나감 → 응답 도착 시 푸시 알림 → 알림 눌러 결과 확인 |
| 5 | E 카드사 거절 | 결제 실패(카드사 거절), 출금 없음 |
| 6 | F 잔액 부족 | 잔액 5,200원 → 결제 실패(잔액 부족), 출금 없음 |
| 7 | G 승인 후 환불 요청 | 승인 후엔 취소 버튼이 없고 환불 요청만 가능 → 환불 완료, 잔액 복원 |

### 재생 제어
| 키 | 동작 |
|---|---|
| P | 일시정지 / 계속 (모든 타이머·카운트다운이 멈춤) |
| N | 다음 단계로 건너뛰기 (예: 10초 대기를 바로 넘김) |
| R | 초기화 (거래번호가 다시 TX-0001부터) |

### 발표자 콘솔 버튼
| 키 | 버튼 | 설명 |
|---|---|---|
| O | 네트워크 끊기 | 오가는 중이던 요청·응답이 유실됨. 거래번호는 유지 |
| I | 네트워크 복구 | 1.2초 후 연결 → 진행 중 거래를 같은 번호로 자동 재시도 |
| D | 응답 지연 켜기·끄기 | 켜면 카드사가 응답을 보류 (10초 지나면 '확인 중'). 끄면 보류된 응답이 바로 처리됨 |
| A | 지연된 응답 지금 도착 | 보류 중인 카드사 응답을 지금 보냄 (확인 중이면 알림으로 결과 표시) |
| X | 거절 켜기·끄기 | 다음 승인 판단을 카드사 거절로 |
| B | 잔액 부족 켜기·끄기 | 연결 계좌 잔액을 5,200원으로 (결제 금액 12,800원) |
| C | 결제 취소 | 앱의 '결제 취소'와 같음 (3초 안에만 가능, 그 뒤엔 이유를 토스트로 안내) |
| F | 환불 요청 | 앱의 '환불 요청'과 같음 (승인 완료 후 1회) |

콘솔의 **현재 상태**에서 거래번호, 요청 시도 횟수, 서버 수신 횟수, **출금 횟수**, 잔액을 실시간으로 볼 수 있습니다. 이벤트 타임라인에는 앱·서버·카드사가 한 일이 순서대로 남습니다.

### 즉석 시연 팁
- "승인 요청 중에 끊기면?" → 승인 요청 화면에서 **O** → 앱에 "같은 거래번호 TX-0001로 자동 재시도" 표시 → **I** → 결제 완료, 출금 1회.
- "카드사가 늦으면?" → **D** 후 결제 → 10초 뒤 확인 중 → 홈으로 → **A** → 알림.
- 확인 중에는 새 결제를 시작할 수 없습니다(토스트로 안내).

## 규칙 요약 (자세한 내용은 RULES.md)
- 지문은 1초 이상 눌러야 인증되고, 중간에 떼면 아무 일도 일어나지 않습니다.
- 인증 후 3초 동안은 취소할 수 있고, 이 동안에는 아무것도 전송되지 않습니다.
- 거래번호는 3초가 끝나는 순간 한 번만 만들어지고, 재시도·재연결·확인 중 전환에도 바뀌지 않습니다.
- 서버는 거래번호를 기준으로 처리하므로 같은 번호가 여러 번 와도 출금은 한 번입니다.
- 승인 대기가 10초를 넘으면 '확인 중'이 되고, 결과는 나중에 알림으로 옵니다.
- 잔액이 결제 금액보다 적으면 거절되고 출금되지 않습니다.
- 승인된 결제는 취소할 수 없고 환불 요청만 가능합니다(거래당 1회).

## 무엇이 가짜인가
- QR 카메라, 지문 센서, 네트워크, 페이링 서버, 카드사, 계좌 잔액, 푸시 알림은 모두 브라우저 메모리 안의 시뮬레이션입니다. 실제 전송·결제는 없습니다.
- 가맹점(브루잉랩 성수점), 카드(가온 체크카드 ****1234), 금액은 가상 데이터입니다.
- **실제 규칙 시간(그대로)**: 지문 1초, 취소 가능 3초, 확인 중 전환 10초.
- **발표용으로 압축한 시간**: QR 인식 1.5초, 승인 왕복 2초(전송 0.4 + 카드사 1.2 + 응답 0.4), 재연결 1.2초, 환불 처리 2.5초, 알림 배너 5초.
- 시안이 없어 아래 화면은 모두 기본 디자인(페이링 보라 #5B3CF5)으로 새로 만들었습니다. 검토 부탁드립니다: 홈, QR 스캔, 결제 확인, 지문 인증, 3초 카운트다운, 승인 요청 중, 확인 중, 결제 완료, 결제 실패(잔액 부족/카드사 거절), 결제 취소, 환불 요청 접수, 환불 완료, 푸시 알림 배너.

## 파일
| 파일 | 역할 |
|---|---|
| `index.html` | 데모 화면 틀 (기기 + 콘솔) |
| `domain.js` | 결제 규칙 전부 (상태, 전이, 시간표, 모의 서버/카드사, 시나리오) — 규칙을 바꿀 땐 여기만 |
| `views.js` | 앱 화면, 버튼 동작, 콘솔 버튼·상태 표시 |
| `styles.css` | 색·글꼴·간격 토큰(`:root`)과 화면 스타일 |
| `sim.js`, `ui.js` | 가상 시계·일시정지·시나리오 재생, 렌더링 엔진 (보통 수정 불필요) |
| `RULES.md` | 규칙 명세 (사전 승인됨, 가정 항목 확인 필요) |
| `test.cjs` | 규칙 테스트: `node test.cjs` |
| `browser.test.cjs` | 실제 브라우저 검증 + 스크린샷: `node browser.test.cjs` (Playwright 필요) |
| `server.cjs` | 선택용 로컬 서버 |
