# 데모배달 주문 추적 데모

투자자 데모데이용 배달앱 주문 추적 시뮬레이터. 서버·설치 없이 `index.html`을 더블클릭하면 열리고 인터넷 없이도 동작합니다.

## 여는 법
1. `delivery-demo.zip` 압축을 풉니다.
2. `index.html`을 Edge 또는 Chrome으로 엽니다.
3. 발표 화면에서는 오른쪽 위 **발표 모드**를 누릅니다(콘솔이 숨고 휴대폰 화면만 가운데 보입니다). 단축키는 발표 모드에서도 작동합니다.

(선택) 로컬 서버로 보고 싶으면: `node server.cjs` 실행 후 http://127.0.0.1:4173

## 발표 진행법
- **본편:** `1`을 누르면 정상 배달이 자동 재생됩니다(약 35초). 주문 → 가게 수락 → 조리 → 라이더 배차 → 픽업 → 지도에서 라이더 이동 → 배달 완료 → 리뷰 요청.
- **질문이 나오면:** `P`로 멈추고 설명하세요. 아래 시나리오나 제어 키로 상황을 바꿔서 보여주면 됩니다. 제어 키를 누르면 자동 재생은 멈추고 그때 상태는 그대로 남습니다.

| 키 | 시나리오 | 보여주는 것 |
|---|---|---|
| 1 | A 정상 배달 | 30분 걸리는 흐름을 35초에. 상태바 시계가 19:00→19:32로 흐름 |
| 2 | B 가게 거절 → 자동 환불 | 거절 즉시 21,000원 환불 카드 |
| 3 | C 배차 지연 → 안내 + 쿠폰 | 배차 대기 타이머가 5:00이 되는 순간 지연 안내 + 3,000원 쿠폰, 도착 예정 +10분 |
| 4 | D 고객 취소 | 수락 후(조리 전) 취소 → 환불 / 두 번째 주문은 조리 중 취소 시도 → 불가 안내 |
| 5 | E 배달 중 주소 변경 | 요청만으로는 경로가 안 바뀜 → 라이더 승인 후 현재 위치에서 회사로 재경로 |
| 6 | F 라이더 통신 끊김 | 지도 마커가 회색 "마지막 위치"에 고정 → 복구 시 실제 위치로 이동 |

E, F는 "배달 중"까지 같은 규칙 엔진으로 빨리 감은 뒤 시작합니다(타임라인에 모든 이벤트가 남음).

### 재생 키
| 키 | 동작 |
|---|---|
| P | 일시정지 / 계속 (모든 시계·지도 이동이 멈춤) |
| N | 다음 단계 (남은 대기 시간을 건너뜀, 일시정지 상태 유지) |
| R | 초기화 (주문번호가 다시 ORD-0001부터) |
| 1–6 | 시나리오 A–F |

### 상황 제어 키 (콘솔 버튼과 같음)
| 키 | 동작 | 언제 되나 |
|---|---|---|
| O | 고객: 주문하기 | 진행 중 주문이 없을 때 |
| C | 고객: 주문 취소 요청 | 조리 전이면 취소+환불, 조리 후면 화면에 불가 안내 |
| M | 고객: 주소 변경 요청(회사) | 배달 중, 주문당 1회 |
| A | 가게: 수락 | 주문 접수 상태 |
| X | 가게: 거절 → 자동 환불 | 주문 접수 상태 |
| S | 가게: 조리 시작 | 가게 수락 상태 (자동 응답을 끈 경우) |
| D | 라이더 부족 ↔ 정상 | 언제나. 부족 상태로 배차 5분이 지나면 쿠폰 |
| L | 라이더 통신 끊김 ↔ 복구 | 배차된 라이더가 있을 때 |
| Y | 라이더: 주소 변경 승인 | 요청 대기 중 + 라이더 통신 연결 |
| U | 라이더: 주소 변경 거절 | 같은 조건 |

콘솔의 **가게 자동 응답** 체크를 끄면 가게가 스스로 수락하지 않아서 "가게 확인 중" 상태에 머뭅니다. 거절·수락을 직접 보여줄 때 쓰세요.
조건이 안 맞는 키를 누르면 화면에 이유가 뜹니다(예: "주문 접수 상태에서만 거절할 수 있어요").

**질문별 추천 동선**
- "가게가 거절하면?" → `2`, 또는 자동 응답 끄고 `O` → `X`
- "라이더가 안 잡히면?" → `3`, 또는 `D` 누른 채 주문
- "주문 취소는?" → `4`
- "주소를 바꾸면?" → `5`, 거절 경우는 `5` 2단계에서 `U`
- "라이더 GPS가 끊기면?" → `6`, 또는 배달 중 `L`

## 규칙 요약
- 진행 중 주문은 하나. 주문하기를 여러 번 눌러도 주문번호는 하나.
- 가게는 주문 접수 상태에서만 거절할 수 있고, 거절하면 즉시 자동 환불.
- 고객 취소는 조리 시작 전(주문 접수·가게 수락)까지만. 조리가 시작되면 "취소할 수 없어요".
- 라이더 배차는 조리 시작과 동시에 탐색. 배차 대기가 정확히 5분이 되면 지연 안내 + 3,000원 쿠폰(주문당 1회), 도착 예정 +10분.
- 조리가 끝났는데 라이더가 없으면 "조리 완료·라이더 대기". 라이더가 도착하면 픽업.
- 주소 변경은 배달 중에만, 주문당 1회. 라이더가 승인해야 경로가 바뀌고, 승인 전에는 기존 주소로 계속 이동. 응답 전에 도착하면 요청 만료.
- 라이더 통신이 끊기면 앱은 끊긴 순간 위치를 "마지막 위치 · N분 전"으로 보여줌. 그동안의 도착·픽업은 복구될 때 반영. 끊긴 라이더는 주소 변경에 응답 못 함.
- 배달 완료 1분 뒤 리뷰 요청. 별점 탭으로 작성(1회).

자세한 전이표·시간표·가정: `RULES.md`

## 가짜로 처리한 것 / 압축한 것
- **시간:** 이야기 1분 = 데모 1초(60배). 배차 5분 규칙도 이 시계로 정확히 5:00에 발동합니다. 실제 30~40분 → 데모 약 35초.
- 결제·환불·쿠폰: 화면 표시만. 실제 결제 없음.
- 지도: 가상 동네 그림(SVG). 실제 지도·GPS·주소 아님.
- 가게·라이더 응답: 시간 규칙 또는 발표자 콘솔.
- 상호·라이더·주소 모두 가상("한입분식", "김바람", "데모구 샘플로 12").
- 새로고침하면 처음부터. 저장되는 데이터 없음.
- 실제 제품으로 키울 때는 새로 만드는 것을 권장합니다(타이머와 상태가 메모리 시뮬레이션).

## 파일
| 파일 | 역할 |
|---|---|
| `index.html` | 화면 틀: 휴대폰 프레임 + 발표자 콘솔 |
| `domain.js` | 주문·배차·환불·주소 변경·통신 규칙, 시간표, 시나리오 |
| `views.js` | 앱 화면, 지도, 콘솔 버튼·단축키·상태 표시 |
| `styles.css` | 색·글꼴 토큰과 화면 스타일 (브랜드 색은 `--accent`) |
| `sim.js`, `ui.js` | 가상 시계·재생·렌더링 엔진 (보통 수정 안 함) |
| `RULES.md` | 규칙 명세 |
| `test.cjs` | 규칙 테스트 (`node test.cjs`) |
| `browser.test.cjs` | 실제 브라우저 검증 + 스크린샷 (`node browser.test.cjs`, Playwright 필요) |
| `server.cjs` | 선택용 로컬 서버 |

## 검증 결과
- 규칙 테스트 `node test.cjs`: **50개 모두 통과**. 전이, 예외 5종, 불변식, 5분 경계(4:59 없음 / 5:00 지급), 6개 시나리오가 끝까지 재생됐을 때와 일시정지 + N으로만 넘겼을 때의 최종 상태가 같은지.
- 브라우저 검증 `node browser.test.cjs` (Edge, Playwright): **통과**.
  - 주문 버튼 연타해도 주문 하나, 실제 시간으로 가게 자동 수락, 조리 전 취소 → 환불, 조리 중 취소 → 불가 안내
  - 주소 변경 요청 → 승인 전 주소 유지 → 승인 후 지도 마커 이동
  - 통신 끊김 시 마커 고정 → 복구 시 갱신, 일시정지 시 지도도 멈춤, 리뷰 별점 작성
  - 6개 시나리오를 일시정지 상태에서 N으로 끝까지, 단계마다 스크린샷
  - 발표 모드에서 단축키 동작, `file://`로 직접 열기, 375px 폭 가로 스크롤 없음
  - 깨진 이미지 0, 콘솔 에러 0, 외부 요청 0
